# Short links

Any unclaimed path on the site can be a short link. They're stored in Postgres and managed from [the admin](admin.md).

## Shapes

A link resolves through `src/app/[...link]/page.tsx`, in one of two shapes:

```
/<slug>          tag = "" (the default bucket)
/<tag>/<slug>    namespaced, e.g. /talk/react-india
```

Anything with three or more segments is a 404, and so is a path nothing claims. The resolver is a catch-all, so keep it last and add new top-level routes to the reserved list below.

Slugs are unique per `(tag, slug)`. A link has one primary slug and up to 24 aliases, so `/github` and `/gh` can point at the same place. Tags and slugs are lowercase letters, numbers, and single dashes.

## What a link does

- **Plain redirect.** With no title, description, or OG enabled, the visitor goes straight to the target. The redirect is temporary, or permanent if the link is marked so.
- **Preview first.** If a link has a title, a description, or OG enabled, it renders a small page with preview metadata and then redirects in the browser. That page exists for the moment you post the link somewhere that unfurls it. It sets Open Graph and Twitter tags, and it's `noindex`. With OG enabled and no image, the card is generated by `/og` from the title and description. A fallback link and `noscript` message cover browsers that don't run the redirect.
- **Targets** must be `http://`, `https://`, or `mailto:` URLs, up to 2048 characters.
- **Disabled links** don't resolve, so they 404.

Clicks are counted in `after()`, so the redirect isn't waiting on the write, and only the counter is stored. No IP, hash, or timestamp. See [Database](database.md).

## Reserved paths

Slugs and tags can't use a path the site already owns. The list is [`src/lib/reserved-segments.ts`](../src/lib/reserved-segments.ts): `admin`, `api`, `og`, `blog`, `blogs`, `branding`, `guestbook`, `llms`, `privacy-policy`, `projects`, `resume`, `sitemap`, `robots`, `icon`, `apple-icon`, `stats`, `svg`, `_next`, and the two favicons.

When you add a new top-level route, add it there too. Otherwise a link could claim the path, and the short-link domain wouldn't know to send the path to the main site.

## A second domain

Set `SHORTLINK_DOMAIN` to serve the same links from a shorter domain pointed at this deployment, so `/talk/react-india` also works at `short.example/talk/react-india`. `NEXT_PUBLIC_SHORTLINK_DOMAIN` is accepted as a fallback.

[`src/proxy.ts`](../src/proxy.ts) handles that host before anything else:

- A slug on that host resolves as a short link, without Clerk's middleware.
- Anything that belongs to the main site (the home page and every reserved path) is redirected to the main domain with a 308.
- `www.` on the short-link domain is treated the same.

Add the domain to the same Vercel project, or the proxy never sees its requests. See [Deployment](deployment.md).

## Managing links

Use the admin page. It creates, edits, enables and disables, and deletes links, and shows click counts. The same schema checks every save, so a slug that conflicts with another link or a reserved path is rejected with a message.

To seed a few, edit and run `pnpm db:seed:links`. It skips slugs that already exist.
